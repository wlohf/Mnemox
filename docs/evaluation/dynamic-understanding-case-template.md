# 动态用户理解评测案例格式

用于 DI-0 后续真实任务评测与 DI-1～DI-4 验收。合成案例验证工程约束；真人效果、抽取质量与成本分别记录。当前只读证据接口不提供历史修订快照，不能用今天的任务状态冒充过去可见信息。

每个案例保留以下内容，可随具体测试使用 JSON fixture 或人工记录，不要求新增评测框架。

| 字段 | 必填内容 |
| --- | --- |
| case_id / kind | 稳定标识；合成、授权脱敏或真实使用 |
| question / context | 用户实际问题、任务场景、用户时区、观察窗口 |
| observed_cutoff | 当时已知信息的截止时间；发生时间与接收时间分别保存 |
| discovery_inputs | 冻结的规范输入、来源 ID/版本、数据质量、缺失与排除原因 |
| experience_groups | 原始经历与派生摘要的同源关系；相关会话不能横跨发现/验证样本 |
| expected_boundary | 应仅陈述观察、提出可检验估计、请求背景或暂不下结论；禁止的泛化 |
| output / citations | 实际输出及引用；每条引用能否回到当时可见来源 |
| later_inputs | 截止时间之后的支持、反例、用户纠正及来源变化，不能回灌发现输入 |
| expected_revision / actual_revision | 判断应保持、限制范围、争议、替代或撤回，以及实际处理结果 |
| user_outcome | 建议展示、采纳、行动、领域结果、反馈分别记录；无响应为未知 |
| quality_review | 依据是否支持措辞、是否忽略反例/偏差、删除后是否仍可检索；支持/反对/未验证分别列出 |
| runtime / cost | SQL/图/降级实际路径、模型及输入版本、耗时与实际用量；没调用的能力不记收益 |

首批回放至少覆盖：空数据、单一场景、小样本、同源大量记录、事件重放、Demo、缺失时长/时区、真实长时异常、近期行为变化、用户纠正、删除和两用户隔离。后续再增加候选引用捏造、AI 自我引用、迟到证据、图失效和模型重抽取版本差异。

不要把使用天数、记录条数或模型自报概率作为“判断已可靠”的验收条件。真实任务先记录失败与未知，再在下一轮独立观察前确定目标和停止条件；关联解释与因果验证分开。
