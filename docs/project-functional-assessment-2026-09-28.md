Mnemox 功能闭环与内测准备评估（2026-09-28）
========================================

评估对象是当前工作区（包括尚未提交的修复），不是历史 v1.3.0 安装包。范围为功能、数据一致性、故障恢复和交付准备，不包含视觉样式。本次未修改业务代码、启动既有服务、升级用户数据库或调用真实 AI 供应商。

交付范围补充：以下账号运营、准入、平台费用及用户支持建议主要面向你托管的网站或面向普通用户的安装包。若定位为开发者源码自部署，完整邮件找回、邀请管理、平台计费等可以后置，以配置文档、人工/命令行账号恢复和备份指引替代。AI 配置、依赖可安装、功能一致性和数据恢复仍需保证；取得源码不能替代这些能力。开源与闭源本身不决定是否需要托管服务的运营功能。

**总体判断**

项目已超过概念验证阶段，具备较完整的学习工作台和 AI 教练工程底座；适合定位为“内部 Alpha，正在收敛为封闭内测候选”。基础能力大多存在，但学习计划的状态一致性、内容保护和真实环境验收还不足以支撑“整体闭环完成”或“稳定公开 Beta”的判断。

需要分别回答三件事：

- 功能闭环：主体已连通，计划与目标任务之间仍有实际断点。
- 数据与交付闭环：幂等、隔离、迁移和恢复已有大量实现，近期修复仍需形成可复现的候选版本并完成目标环境验收。
- 产品价值闭环：有学习事件、建议归因和行为指标，但没有足够真人连续使用证据证明建议能稳定改善学习行为。

**各条主链的现状**

| 用户流程 | 当前判断 | 主要边界 |
| --- | --- | --- |
| 注册、登录、配置 AI、开始使用 | 基础可用 | 已有新手引导和 Demo；缺少改密、找回密码、账号退出后的数据处置等完整账号生命周期 |
| 上传资料 → 检索问答 → 笔记/目标 | 主体实现 | 有关键词降级、引用、来源版本及索引重试；真实模型质量、大文件解析资源治理仍需验收 |
| 目标 → 任务 → 番茄钟/学习事件 | 主体实现 | 近期新增身份幂等、复习幂等和账户隔离；今日统计仍有时区边界错误 |
| 今日计划 → 执行 → 完成反馈 | 尚未完全闭环 | Markdown 勾选与 Task 状态分离；重新生成会覆盖复盘；“AI 生成”的 AI 分支失效 |
| 错题/Anki → 复习 → 调度/证据 | 主体实现 | 有 FSRS/降级、复习幂等、Anki 离线队列；跨设备、跨日、重启仍需真实端到端验收 |

| Claim/关联/图路径/时态图 | 可选实验能力 | 工程实现较多，主要开关默认关闭；真实中文/双语人评未完成，不应作为默认内测承诺 |

**A. 已确认的功能问题，建议优先处理**

1. **生成计划会覆盖已保存内容（优先级高，API 已复现）。**
   保存当天计划，勾选事项并写入自己的复盘后，再次请求生成计划，已保存的复盘和勾选状态均消失。后端直接替换 `DailyPlan.content`；页面“AI 生成”直接调用该接口。应改为先生成草稿，明确追加/合并/替换，并保留历史版本或可撤销快照。
   证据：[plans.py](../backend/app/routers/plans.py) 的 `generate_daily_plan`，尤其第 344–354 行；[PlansPage.tsx](../frontend/src/pages/PlansPage.tsx) 的 `handleGenerate`。

2. **计划完成不等于目标任务完成（优先级高，API 已复现）。**
   创建真实目标任务，生成当天计划，在计划中勾选并保存，任务仍为 `pending`。首页也把 dashboard 任务与 plan 文本分为两套更新路径。用户可能看到计划已完成，而目标、今日任务和学习事件仍显示未完成。
   应给关联任务的计划项保存稳定 `task_id`，通过领域接口完成任务并记录事件；独立文本清单则明确是个人勾选，不能冒充任务/复习完成。复习完成仍应由真实复习提交产生，不能直接从 Markdown 勾选推断。
   证据：[plans.py](../backend/app/routers/plans.py) 的 `upsert_plan`；[ObsidianLayout.tsx](../frontend/src/components/Layout/ObsidianLayout.tsx) 第 2172 行起的列表合并与 `handleToggleTodayTask`；[daily_plan.py](../backend/app/models/daily_plan.py) 虽有 `task_ids`，普通生成/保存未建立项目级映射。

3. **“AI 生成计划”的 AI 分支始终退化（代码与模块检查已确认）。**
   第 308 行导入 `app.services.ai_client.get_ai_client`，仓库没有该模块；随后 `except Exception: pass` 吞掉异常。因此规则清单可以生成，但这里配置真实 Key 也无法获得预期的 AI 建议。应接入现有 `AIProviderFactory`，并让响应区分规则生成、AI 成功和 AI 失败降级。不能据此推断聊天或“明镜追问”的 AI 也不可用，它们使用不同实现。
   证据：[plans.py](../backend/app/routers/plans.py) 第 305–320 行；[learningApi.ts](../frontend/src/services/learningApi.ts) 的 `generateDailyPlan` 确实调用此路由。

4. **“今日”统计未统一用户自然日（隔离时钟与数据库已复现）。**
   `learning/dashboard` 以服务器 `date.today()` 和本机零点查询 UTC 存储的计时数据，没有用户时区转换。模拟 UTC 服务器 2026-09-28 01:00，一条北京时间当天 02:00 完成的番茄钟被统计为今日 0 条。前端计划日期又按浏览器本地日期计算，跨日时还有日期不一致的可能。
   应统一账户 IANA 时区，先计算用户当地一天，再转换为 UTC 查询区间；一并核对今日任务、计划、热力图和周报的日期口径。
   证据：[learning.py](../backend/app/routers/learning.py) 第 336–375 行；[PlansPage.tsx](../frontend/src/pages/PlansPage.tsx) 的日期处理。

5. **计划编辑缺少与笔记同等级的内容保护（代码确认）。**
   编辑内容只保存在页面 state，切日期会替换 `editContent`，未找到该页面的持久草稿、离开确认或版本冲突检测。多设备保存同一天计划也没有同步协议中的版本条件，后保存者可覆盖前者。建议复用已有笔记草稿思路，补本地持久草稿、切换保护及服务端版本冲突；不必先把所有功能改为离线。
   证据：[PlansPage.tsx](../frontend/src/pages/PlansPage.tsx) 第 94–96、153–158、182–194 行；[plans.py](../backend/app/routers/plans.py) 第 434–452 行。

6. **特殊重复注册组合会返回 500（API 已复现，较低优先级）。**
   已有 A、B 两个账号时，提交 A 的用户名和 B 的邮箱，OR 查询返回两行，而代码调用 `scalar_one_or_none()`，触发服务端错误。应返回受控的注册信息不可用提示，并处理唯一约束竞争。
   证据：[auth.py](../backend/app/routers/auth.py) 第 148–152 行。

**B. 已存在的能力边界及应补的产品功能**

- **账号生命周期**：路由目前只有注册、登录、退出和读取当前用户，没有改密、找回密码、邮箱核验、注销入口。熟人内测可以先提供明确的人工恢复渠道；开放注册前至少补改密/恢复、准入控制和数据清理方案。无需为了小规模内测立即建设复杂权限后台。
- **数据带走与恢复**：已有 PostgreSQL 备份/恢复演练脚本、Anki CSV 和学习报告导出，不能表述为“没有备份”；但没找到普通用户的完整工作区导出/恢复入口。桌面应覆盖 SQLite、附件、加密密钥及尚未同步的本机数据；服务器备份应覆盖数据库、原始附件和必要配置，投影可重建。验收标准应是恢复后可继续学习。
- **Demo 与真实学习混合**：Demo 在当前账户下创建完成任务、番茄钟、错题、记忆，并重算画像；没有独立 Demo 空间或一键清理主链。新手引导还按“已有记录”判断闭环完成，导入 Demo 即可满足，不代表用户亲自完成过学习。建议独立体验账户/空间，或统一标记、排除统计并提供清理，避免干扰内测行为数据。证据：[system.py](../backend/app/routers/system.py) 的 `seed_demo_workspace`、`_build_onboarding_stage`。
- **完整删除语义**：同步幂等回执持久保存响应正文，未找到对应的保留/脱敏/删除清理流程。正常记录删除与所有历史副本清理应区分；设计保留期限和删除语义时仍需保留防重放能力，不能简单清空回执。证据：[sync.py](../backend/app/models/sync.py)、[同步工具](../backend/app/utils/sync.py)。
- **桌面与网站不是同一个共享账户后端**：桌面启动本地服务并强制使用用户目录 SQLite。现有离线同步解决浏览器/客户端到其当前后端的一致性，不等于两台独立桌面安装或桌面与网站已经云同步。初次内测必须讲清楚数据位置；跨端云同步属于单独产品范围。证据：[runtimePaths.js](../desktop/src/runtimePaths.js) 的 `buildBackendEnv`。
- **问题反馈与诊断**：已有领域日志、worker 健康、outbox 和 Agent 运行记录。建议再加一个用户可找到的问题反馈渠道和脱敏诊断包，至少包含版本、系统、失败操作、请求/运行标识及待同步数量；不自动上传笔记、对话或 Key。

**C. 内测交付与运行风险**

- **默认测试依赖缺失（同日已修复）**：初评后端全量得到 720 passed、4 failed、50 skipped、70 subtests passed。4 个失败全部位于 `test_graphiti_temporal_service.py`，根因是缺少 `graphiti_core`。同日已把 Graphiti SDK 纳入标准依赖，完整复验为 **725 passed、49 skipped、70 subtests passed**，真实 Neo4j/Graphiti 集成另有 **6 passed**。这是依赖安装修复，不代表图功能已在现有部署启用。详见[修复与验证记录](updates/2026/2026-09-28_graph-sdk-dependencies.md)。
- **候选版本还未冻结**：工作区有大量已修改和未跟踪文件，版本仍统一为 1.3.0。版本一致性 preflight 通过不等于可以复用已有发布版本。需固定候选提交、更新版本/迁移说明，再在同一提交构建工件。
- **真实 E2E 覆盖不足**：CI 浏览器任务调用 `selftest-ui.mjs`，其 `mockRoutes` 拦截 API；真实 HTTP 的 `selftest-sync.mjs` 存在，但未接入该 CI 浏览器任务。现有 ASGI API 测试和浏览器模拟测试不能替代完整产品使用链的真实前后端验收。建议将真实同步和主学习流程纳入独立测试环境。
- **文件解析资源边界**：已有大小、格式、DOCX 解压和字符数限制，也有 `wait_for(to_thread(...))` 超时；该超时不能强制终止已在运行的解析线程。面向公共上传应补可终止的进程/worker、并发限制及失败任务重试。本次没有对异常大文件实施压测，此项是代码风险分析。证据：[material_service.py](../backend/app/services/material_service.py) 第 55–67 行。
- **成本控制范围要明确**：Agent 和知识抽取已有预算，不代表所有聊天、embedding、联网搜索等路径都有统一账户总预算。内测可先采用用户自备 Key；若由运营者承担模型费用，应明确所有计费入口的总限额、并发、超额提示和关闭开关。
- **旧数据升级不能省略**：当前迁移 head 已到 `20260925_28`；旧 Docker 文件目录、桌面来源、历史计时时区和旧 Provider Key 有专门处理流程。前后端还需一起升级，避免新复习 `attempt_id` 契约与旧客户端不兼容。参见[后续升级](remaining-hardening-upgrade.md)、[运行数据升级](runtime-data-upgrade.md)、[桌面来源升级](desktop-origin-upgrade.md)。
- **本机运行状态**：只读检查时，本机 Compose 中 `mnemox-backend-1` 已退出，前端和数据库仍在运行。此观察只针对本机这套部署，未核实其他入口；没有自动重启或重建服务。若准备分享这套站点，需要先按数据升级流程验证后端健康。

**建议的内测范围与验收标准**

先做 5–10 人、持续 1–2 周的邀请内测，范围聚焦：注册/AI 配置 → 导入自己的资料 → 创建目标和今日任务 → 完成专注/笔记 → 完成一次复习 → 第二天读取记录并获得下一步建议。规模和周期是建议，不是现有完成事实。

优先级顺序：

1. 修复计划覆盖、计划/任务完成一致性、AI 失效分支、时区及计划草稿保护；修复重复注册错误。
2. 修好默认测试门禁，固定候选版本；准备可恢复备份、账号恢复渠道和已知限制说明。
3. 完成真实前后端流程：新账号、真实少量模型调用、双账号隔离、刷新/重启、断网重连、丢失响应重试、冲突、资料删除、跨日统计。失败时不重复扣次数、不丢已保存内容、不错误改变掌握度。
4. 根据分享方式补验收：Windows 完成安装/启动/退出/旧版升级/卸载保留数据及更新失败回退；网站完成 HTTPS/Cookie/代理、邀请准入、并发边界、备份恢复和健康告警。
5. 连续观察首次真实学习完成、第二天恢复、建议实际执行、到期复习完成、错误与数据恢复反馈；Demo 和模拟数据不计入产品效果结论。

当前不建议把 Neo4j、Graphiti、语音、多 Agent、AnkiConnect 或复杂付费系统作为首轮内测前置条件。保留已有实验能力，但先确保用户的一次真实学习及第二天继续使用稳定可靠。
