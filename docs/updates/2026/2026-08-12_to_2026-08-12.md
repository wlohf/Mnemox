# 2026-08-12

## 本周期目标

收口 projection outbox 运维闭环的多实例心跳与指标扩展性风险，并将该闭环作为独立提交落库。

## 已完成内容

- `OUTBOX_WORKER_ID` 现在是部署可读的逻辑前缀。应用创建 worker 时会追加受 120 字符存储上限保护的 hostname、PID 与随机运行时令牌，确保同一前缀的副本不会覆盖或停止彼此的心跳。
- 新增回归：两个使用同一配置前缀的 worker 写入独立心跳；停止其中一个后，另一个仍被聚合快照识别为活跃，且 ready 队列不会误报 `projection_outbox_no_active_worker`。
- 运维快照只聚合未完成的 `pending`、`processing` 和 `failed` 任务，不再把无限增长的 `processed` 历史计入队列总量。
- 新增 Alembic 修订 `20260812_06` 和 SQLite 轻量迁移索引 `ix_projection_outbox_operations_active`，以局部索引支撑上述活跃队列聚合。
- 私有运维快照会检测 `OUTBOX_WORKER_RETRY_POLICY_VERSION` 相同但 `OUTBOX_WORKER_MAX_ATTEMPTS` 不同的部署漂移，并输出 `projection_outbox_retry_policy_config_conflict` 关键告警及对应 Prometheus 指标。消费者继续快速失败；告警扫描保持只读，确保该漂移本身不会掩盖告警。
- 活跃心跳现在同时区分“最近轮询失败”的 worker：当轮询错误严格晚于最近成功时间，且不是同一批次的投影级失败时，聚合会输出 `error_workers` 和 `projection_outbox_worker_poll_error` 关键告警，避免持续心跳掩盖实际不消费。
- 全局 worker 保持直接 `FOR UPDATE SKIP LOCKED` 领取，不会预选并限制候选任务 ID；这使竞争中的实例可以跳过忙行，继续领取其他用户的就绪任务。用户范围调用仍以 advisory lock 隔离其用户范围，并在冲突时通过 `SKIP LOCKED` 跳过已领取行。

## 发布与验证边界

- `OUTBOX_WORKER_ID` 不再是稳定持久主键，不应依赖其完整值进行部署级筛选；需要人为可读分组时使用配置前缀。
- 修改重试上限必须同时提升 `OUTBOX_WORKER_RETRY_POLICY_VERSION`。受保护 `/internal/outbox/metrics` 中的策略冲突指标是部署就绪检查的输入；公开 `/health` 仍只承担轻量存活检查，不执行数据库队列聚合。
- SQLite 回归与 PostgreSQL 离线 DDL 验证不能替代正式 PostgreSQL 16 多实例验收。发布窗口仍需验证并发策略升级、`SKIP LOCKED` 领取、同前缀实例的独立心跳以及优雅停止。
