# 更新记录：服务事务所有权架构守卫

## 本周期目标

- 把剩余服务层提交点从隐含实现细节变成可审计的架构契约。
- 阻止后续功能在领域查询或投影函数中悄悄提交调用方的 unit of work。

## 已完成

### 1. 事务所有权清单

- 新增共享事务策略，提交所有者只允许两类：跨非事务存储保存恢复检查点的 `durable_workflow`，以及持有独立短 session 的 `independent_worker`。
- 当前同步所有者限定为 Agent 完整任务生命周期、资料规范数据与向量投影协调，以及检索投影在向量调用前后的状态检查点。
- 当前 worker 所有者限定为 AgentRuntime、Agent 过期任务回收和 projection outbox 的独立事务。
- 每个所有者必须提供非空理由；普通领域/投影函数继续遵循 flush-only 默认规则。

### 2. AST 架构门禁

- 测试扫描 `app/services` 与 `app/agents` 中所有 `.commit()` 调用，并与所有权清单做双向核对。
- 新增未登记提交会报告完整限定方法名和源码行；删除或迁移提交后，过期清单项也会失败，避免清单沦为失真的历史记录。
- 画像计算、过期画像刷新、学习快照和 Agent 只读工具另有反向断言，确保它们既不含提交，也不能被登记为事务所有者。

## 数据与回滚

- 本模块不改 schema、事务时序或运行结果，只增加策略元数据和静态门禁。
- 若未来要移除某个提交，应先迁移调用链和补回滚/恢复测试，再同步删除清单项；不得只放宽门禁。

- 当前发现的服务提交方法与策略清单严格相等；未登记和失效条目均为零。

## 已知限制 / 后续事项

- 静态守卫能阻止新增隐式提交，但不会证明已经登记的跨存储 saga 时序绝对正确；资料/检索工作流仍需以失败注入逐步收敛。
- 下一模块在现有脱敏摘要上增加结构化错误码和安全指纹，使任务与投影失败可以聚合定位而无需暴露异常正文。
