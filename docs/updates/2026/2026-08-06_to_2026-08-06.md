# 2026-08-06

## 本周期目标

将已验证的 `projection_outbox` 从请求内恢复入口扩展为应用生命周期管理的常驻消费能力，保留 Review/Anki 的事件级低延迟消费。

## 已完成内容

- 新增 `ProjectionOutboxWorker`：一轮轮询最多处理一个配置批量；每条被认领任务都创建独立 SQLAlchemy session，调用既有 `process_outbox()`，并在认领、投影和状态更新完成后单独提交事务，避免跨概念锁交叉。
- worker 启动后立即处理可领取任务，按配置轮询；关闭时用停止事件唤醒轮询，并在数据库连接关闭前等待当前批次结束。
- 新增 `OUTBOX_WORKER_ENABLED`、轮询间隔、批量大小、最大尝试次数和实例标识配置；默认启用，支持按部署环境关闭或命名。
- FastAPI lifespan 负责启动和停止 worker。worker 仅在 PostgreSQL 上启用，继续依赖现有 `FOR UPDATE SKIP LOCKED` 协调多个应用实例；SQLite/桌面端保留请求内消费并明确标记为单消费者。
- PostgreSQL 的多行消费路径在概念投影前按用户排序取得 transaction advisory lock，避免通用 API、重放和 worker 交错时产生反向概念锁顺序；worker 仍逐行独立提交。
- `/health` 增加本实例的 worker 快照：运行状态、累计批次数、认领/成功/失败数量、最近错误时间及最近持久投影失败时间；不返回主机/进程标识、异常正文、用户、事件或证据内容。
- `run_migrations.py` 用 PostgreSQL session advisory lock 串行化 schema 指纹、baseline stamp 和 Alembic upgrade，使多个应用副本启动时不会并发执行 DDL。
