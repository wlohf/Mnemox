# P1：主动复习检查的用户控制与可观测性（2026-08-27）

## 本周期目标

- 把原本仅能从调试信息推断的 AgentRuntime 后台检查，变成学习者能理解、明确同意并随时关闭的能力。
- 不扩大到自动写入、通用调度、多 Agent 或桌面推送。

## 已完成

- 新增已登录用户专属的 `/api/agent/runtime/proactive-status`：同时返回本人是否允许主动检查，以及当前部署是否存在、是否正在运行后台检查器。
- Agent 页面新增“主动复习检查”卡片：展示同意状态、运行模式、最近成功检查和最近失败；失败时明确说明下个低频周期会重试，且没有修改学习数据。
- 开启前需要二次确认；文案明确只会检查复习积压并生成可选建议，绝不会自动创建任务、改计划或启动番茄钟。
- SQLite / 本地模式会如实显示“仅页面内评估”，不把保存偏好误说成服务器正在后台运行。
- 将 Agent 页面中相互独立的主动检查、本周复盘、北极星指标、Coach 建议与行动回放拆为五个组件；页面本身保留状态加载、确认和导航编排，避免后续扩展一处功能时影响其他行为闭环。

## 边界与降级

- 后台扫描仍只适用于已有的 PostgreSQL AgentRuntime 部署；本地 SQLite 保持现有的请求内 Coach 评估，不引入隐藏后台写入。
- 该接口不返回其他用户数据，也不暴露服务器异常正文。
- 本周期不新增自动执行、开放式 Agent、写回 Obsidian 或新的调度场景。

## 验证状态

- 按当前安排，真实 PostgreSQL、Windows、Vault 和真实学习者路径验证暂缓。
- 代码层仅进行类型/构建与静态检查；正式发布结论仍须以独立环境验收为准。

## 后续事项

- 继续按业务边界拆分剩余 Agent 页面区块，并逐步为独立组件补单元级回归。
- 在真实环境恢复验收后，补主动检查的 opt-in、失败重试、关闭后不再扫描和用户隔离证据。
