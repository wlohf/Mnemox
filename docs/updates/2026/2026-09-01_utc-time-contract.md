# 更新记录：UTC 时间契约与核心链路迁移

## 本周期目标

- 消除后端核心链路对服务主机本地时区的隐式依赖。
- 固定“数据库形态、带时区输入和 JSON 边界”三者之间的转换规则，为调度、租约、归因和重放提供一致时间轴。

## 已完成

### 1. 单一 UTC 工具层

- 新增 `app/utils/utc.py`，统一提供 aware UTC、naive UTC 数据库存储、UTC 日期和 RFC 3339 `Z` 序列化。
- naive `datetime` 明确按 UTC 解释；`+08:00` 等 aware 值先换算到 UTC，绝不通过直接删除 `tzinfo` 改变实际时刻。
- 数据库 schema 保持不变，继续使用 naive UTC，以兼容 SQLite 和现有 PostgreSQL 列。

### 2. 核心数据链路迁移

- Agent/AgentKernel、Coach 调度/策略/反馈/实验、学习快照和周报采用共享 UTC 入口。
- `LearningEvent`、时态记忆声明、用户画像、资料检索投影和 projection outbox 的写入时间统一为 naive UTC。
- Agent 行动确认、记忆/事件序列化、投影状态和 worker 健康快照统一输出以 `Z` 结尾的 RFC 3339 时间。
- 无用户时区语义的 Agent“今天”改为 UTC 日历日；不再随服务部署机器时区变化。

### 3. 用户本地时间边界保持显式

- Coach 免打扰、每日触达上限、调度和知识巩固自然周继续由经校验的 IANA 时区计算 UTC 半开边界。
- 这一区分保证“存储和比较使用 UTC”，而“用户看到的自然日/周”仍遵循其明确配置。

## 兼容性与回滚

- 本模块不新增迁移、不重写历史时间值，也不改变用户配置的 IANA 时区。
- API 时间从无后缀 naive ISO 收敛为明确的 `Z`；标准 ISO/RFC 3339 客户端可直接兼容，依赖无时区字符串的旧客户端需同步修正。
- 回滚代码不会触发数据回填，但会重新引入部署主机时区漂移，不建议只回滚部分链路。

## 验证结果

- 统一 UTC 工具与服务解析契约：`6 passed`。
- Agent、Coach、学习事件、画像事务、projection outbox、资料投影和周报聚焦回归：`103 passed, 4 subtests passed`。
- 修复固定日期评测时钟和北极星指标 RFC 3339 `Z` 兼容后，最终后端全量为 `491 passed, 10 skipped, 58 subtests passed`。
- 验证覆盖 naive UTC、带偏移换算、RFC 3339 `Z`、事件/策略/outbox 共享解析，以及既有调度、租约、归因、投影和事务路径。

## 已知限制 / 后续事项

- `north_star_metrics_service` 对既有 naive 历史事件保留明确的墙上时间兼容语义；只有在历史数据迁移与指标对账完成后才能切换解释方式。
- 旧路由和非核心服务仍有直接取本地时间的实现，后续按业务语义分批迁移，不能对用户自然日逻辑做全局机械替换。
- 下一模块统一后台错误摘要的脱敏、长度限制和稳定分类，避免日志、任务结果与投影失败状态保存密钥或完整上游响应。
