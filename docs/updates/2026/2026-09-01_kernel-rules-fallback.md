# 更新记录：AgentKernel 规则 Planner 降级闭环

## 本周期目标

- 让 Kernel 在模型或预算不可用时仍给出安全、可执行、来源明确的下一步。
- 保留失败任务的 checkpoint 和重试能力，不用“降级成功”掩盖原始故障。

## 已完成

### 1. 显式规则降级

- Provider 配置不可用、模型调用错误、输出格式失败、步数耗尽和单次/每日预算耗尽会调用不含 LLM 的稳定规则简报。
- 最多三条行动标记为 `rules_fallback`，结果另存 `fallback.source=rules`、原因、生成时间和风险等级。
- API、任务回放和前端提示区分证据型 Kernel 完成与规则降级，不把降级建议冒充模型结论。

### 2. 失败与行动双轨

- 原 Kernel 任务继续保持 `failed`，租约释放、checkpoint 保留，因此用户仍可从下一步继续或重新运行。
- 降级行动可进入既有持久确认凭据流程；服务端重新校验任务归属、行动快照和目标状态，重复确认仍幂等。
- 取消、租约丢失和持久化异常不生成规则行动，避免并发所有权或存储故障被误判为正常业务降级。

## 失败、降级与数据变更

- 规则简报本身失败时保留原错误和空行动，不覆盖故障原因。
- 本模块无 schema 变更；新增信息写入现有 `AgentJob.result` JSON 和最小化执行日志。
- 降级路径不发起第二次模型调用，不执行自动写入，不扩大用户权限。

## 验证结果

- 后端聚焦回归：`33 passed`，覆盖 Provider 不可用、模型失败、预算耗尽、可行动降级、草案确认、checkpoint 续跑与用户隔离。
- 前端服务测试：`5 passed`。
- 前端生产构建：`npm run build` 通过。

## 已知限制 / 后续事项

- 规则简报使用当前稳定启发式，不等同完成 LangGraph 对照或运行时选型。
- 真实 Provider、PostgreSQL 多实例和桌面候选验收仍按发布门禁执行。
