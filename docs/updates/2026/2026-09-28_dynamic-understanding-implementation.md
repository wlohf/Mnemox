# DI-0 收口、DI-1 实现与 DI-2 经历通道

本次为工作区实现，未提交、部署或修改真实业务数据库。阶段状态以[路线图 0.2](../../roadmap.md)为准。

后续已补齐实体关联检索、时间线、分批重建与恢复、操作入口和 SQL/图对照评测，见[DI-2 补齐记录](2026-09-28_di2-continuous-memory-completion.md)。下方为本批交付时的记录，真实模型验收仍待可用凭据。

## 可以使用的功能

- **可靠记录**：番茄钟、关联任务、明确标注的复盘、Coach 行动结果进入统一经历层。原始记录、AI 追问和行动派生信息分开；Coach 结果可说明尝试过程，不增加独立支持。来源包含对象 ID、内容版本、发生/记录时间、时区及质量标记。
- **计划一致性**：生成计划只返回草案，追加到编辑区后显式保存。保存携带版本；冲突保留账号/日期隔离的本地草稿，页面可保留服务器与本地两份内容再整理。真实任务通过 ID 和任务版本关联，勾选走原任务领域入口；同名任务不再按标题误合并。保存保留修订，Agent 确认追加也使用相同入口。
- **阶段性理解**：在「学习画像 → 阶段性理解与连续记忆」启用分析，主动请求 AI 提出开放观察；查看适用情境、原始依据、未知项、后续信号，纠正、忽略、恢复、撤回或删除。普通重评不需要模型；启用图增强后，更新证据可能同时排队新的经历抽取。
- **后续验证**：冻结发现时刻、发现分组、日期和可观察条件。只有后来发生且后来首次进入证据层的记录参与验证；历史补录、发现数据、同日/同会话重复不增加独立样本。反例使判断进入争议，缺失保持未知。无法操作化的文字判断保持待验证，不转成已确认事实。
- **连续记忆**：复盘、带备注的专注记录和已完成的 Coach 行动使用真正的 Graphiti `add_episode` 提取实体及关系。保存 SDK 输出和来源映射；图丢失时可从 SQL 保存的抽取结果重建，不重新调用模型。支持显式重新抽取。
- **聊天与 Coach 消费**：独立开关控制是否使用这些上下文。用户纠正以用户自述传入，原推测退出消费；候选不更新掌握度或已确认长期事实。图关闭/失败/无命中时，使用 SQL 原始经历，并显示回退原因和每条结果的检索来源。

旧统计也已收口：画像、趋势、时段分布、EDA、番茄钟统计使用同一实际时长与用户自然日口径；未知不是零。旧“时段效率分”、固定画像特征及人为置信度退出新推断与提示。EDA 日均仅按有实际时长记录的日期计算，并说明分母；不把未记录日期当作没有学习。

## 实现边界

- `UnderstandingPreference`、`Experience`、`BehavioralHypothesis`、`HypothesisRevision` 是 SQL 规范对象；现有 `MemoryDeclaration` / Graphiti Temporal V1 保持独立。
- 输入只读取当前用户规范记录，各来源最多 5,000 条，截断会报告。模型发现输入最多近期 60 条、20,000 字符；这不是代表性抽样，不声称覆盖全部历史。
- 首版可操作化验证器适用于番茄钟字段条件；开放文字推测和复盘关系并不因此被证明。Wilson 区间描述未来符合条件的分组记录比例，不是“假设为真的概率”；保留记录偏差、情境覆盖和时间相关性未估计的限制。
- 图检索使用真实抽取后的关系与 BM25；抽取内部使用本地词片段哈希向量和本地排序，明确为词法/结构检索，不宣称语义向量效果，不额外使用外部 embedding/reranker。每个来源版本隔离图空间，通过 SQL 校验后的经历组合形成跨会话回看；不自动合并不同经历为永恒事实，也不声称已实现全局关系冲突消解。
- Graphiti 抽取后的事实描述只作索引；返回聊天的是重新核验的 SQL 原文与来源。既有知识图补弱路径和建议到结果的行动闭环属于 DI-3，不以本次报告代替。

## 持久化、删除和开关

复用 `AgentJob`、现有恢复 worker 的生命周期、事件入口和预算服务。领取租约、预算预留、来源校验、结果保存分别使用短事务，模型调用位于事务外。调用开始前预留预算，失败和中断也保留消耗；预算用尽等到下一 UTC 日。已完成候选阶段不会因为后续图失败重新调用模型。每个用户同一时间只执行一个理解任务。

每个图写入尝试有独立空间并先登记到持久检查点；过期租约/旧来源无法成为可见版本。删除或修改来源立即退出读取，后台清理图失败可重试；修订历史中可能含原文的派生判断会被清除。移除某条分析经历保留原业务记录，并留下排除标记，后续原记录变更不会重新纳入。关闭增强功能不等于删除所有图数据；需要移除时先使用经历移除/清理入口，失败任务保持可见。停用图部署时外部清理要等图服务恢复。

配置：

```env
UNDERSTANDING_ENABLED=true
GRAPHITI_EPISODES_ENABLED=false
UNDERSTANDING_DAILY_MODEL_CALLS=40
UNDERSTANDING_DAILY_TOKENS=160000
UNDERSTANDING_MODEL_TIMEOUT=35
```

用户的分析、图增强、聊天/Coach 消费三个开关默认均关闭。图增强需要现有 `NEO4J_*` 配置和该用户自己的 Coach AI 路由/凭据。安装 SDK 或打开旧 `GRAPHITI_ENABLED` 不会自动启用新经历通道。

真实模型验收脚本：`backend/scripts/evaluate_dynamic_understanding.py`。它使用指定用户现有 Coach AI 配置、合成中文经历、临时 SQL 和显式隔离的本机 Neo4j，输出抽取、检索、判断、实际 token 与配置价格产生的费用；没有价格则费用为 `null`。不会读取该用户业务记录，不删除任何整个数据库。

```bash
# 在 backend 目录；DATABASE_URL 指向存有本人 AI 配置的数据库。
# NEO4J_USER / NEO4J_PASSWORD 对应单独启动的测试实例。
python scripts/evaluate_dynamic_understanding.py --user-id <本人ID> \
  --isolated-graph-uri bolt://127.0.0.1:17687 \
  --output ../docs/evaluation/di2-real-model-result.json
```

输出需按[评测格式](../../evaluation/dynamic-understanding-case-template.md)人评：检查“仍有卡点”“已解决的范围”“方法失效”是否保留，有没有扩大成性格/因果判断，并与 SQL 原始经历基线比较。工程跑通、质量通过、长期收益和部署分别记录。
