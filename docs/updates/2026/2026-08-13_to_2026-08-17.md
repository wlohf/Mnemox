# 更新记录：2026-08-13 至 2026-08-17

## 本周期目标

- 收口 Phase 1 中一条真实 ContextStore 检索链路、Coach 联想归因、Vault 同步安全边界和 SQL 记忆声明基础。

## 指标与范围

- 对应北极星指标：建议执行率与中断恢复的后续归因基础；记忆与笔记数据的可信、可解释和可恢复性。
- 本周期范围：聊天笔记检索、显式知识联想、Vault 拉取同步、人工与自动长期记忆。
- 明确不做：Graphiti/Qdrant/Neo4j Spike、后台 AgentRuntime、自主写回 Obsidian、正式 PostgreSQL 多实例发布验收。

## 已完成

### 1. 功能 / 体验

- 聊天笔记上下文已迁移到 ContextStore；响应携带检索模式，关键词 SQL 仍作为可观测降级。
- 显式知识联想会生成 `association_recall` Coach nudge，页面可查看关联依据，并记录 shown、accepted、completed 生命周期；刷新后可恢复关联详情。
- 记忆管理页可查看声明依据和历史，明确区分人工、自动提炼和 Agent 记录，以及待确认、已确认、已忽略、已标记不准确和已修订状态。

### 2. 修复 / 稳定性

- Vault 同步拒绝越界路径、软链接、超大或非 UTF-8 文件；单个文件读取失败不会覆盖数据库中的已有笔记，界面会显示跳过原因。
- 人工记忆创建或修订写入可审计 SQL 声明，保留主体、类别、值、生效区间、置信度、来源、证据摘要、创建者、规则版本与替代关系。
- 聊天提炼、会话反思和 Agent 学习推断也会创建自动声明；确认、忽略或标记不准确会同步到历史。声明只保存会话/事件等结构化来源，不复制聊天原文摘录。
- 已锁定的人工记忆不能被后台覆盖，也不能被自动路径以相同键创建相互矛盾的候选。

## 失败、降级与数据变更

- ContextStore 不可用或命中不足时保留关键词 SQL 检索；Coach 归因写入失败不阻断联想结果返回。
- Vault 单文件读取失败被记录为跳过，不删除或覆盖存量笔记；扫描不完整时不执行缺失文件标记。
- 记忆声明是 `UserMemory` 当前投影之外的历史表。删除当前记忆时，仅删除该用户对应的声明；自动证据只保留结构化标识。
- 正式 PostgreSQL 仍必须通过版本化 Alembic 升级；本地 SQLite 通过增量 DDL 补齐表和索引，不进行破坏性重建。
