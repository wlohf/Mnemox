# 2026-08-23：SQL 时态记忆冲突、审核、纠错与自动失效

## 本轮交付

- 为 `MemoryDeclaration` 增加稳定事实键、冲突关联和处理原因；Alembic 与 SQLite lightweight migration 升级到 `20260823_12`，自动回填历史事实身份并清理重复的已确认事实。
- 使用 PostgreSQL/SQLite 部分唯一索引保证同一用户、同一事实只能存在一条已确认且尚未结束的声明；用户锁定事实优先于历史自动提炼结果。
- 不同来源产生矛盾结果时创建待审核候选，不覆盖当前事实；同来源的待确认更新同样保留旧事实，直到用户明确接受。
- 接受候选时同步关闭旧声明和旧投影，建立 `supersedes_id` 及一致的生效边界；拒绝或标记不准确只结束候选，原事实保持有效。
- 增加人工纠错原因、有效截止时间、恢复/忽略历史和当前用户的过期维护入口；过期声明保留完整审计。
- 聊天、统一检索、L2 加载、Coach、Agent、反馈排序、笔记召回和学习快照统一排除过期记忆。
- 删除、纠错、事实替代与失效同步移除引用旧事实的核心画像；声明删除清理同一用户下的冲突和替代引用，不影响其他用户。
- 记忆管理页增加冲突对照、候选确认/拒绝、失效状态、有效期设置、纠错原因和跨投影历史。

## 技术边界

- SQLite/PostgreSQL 保持唯一规范来源；Graphiti 仍是有真实能力缺口后才考虑的条件 Spike，不加入运行时依赖。
- 自动候选不得直接覆盖用户确认事实；所有替代决策继续复用现有人工审核 API。
- 本轮不会创建新版本 tag、Release 或桌面安装包；新增 PostgreSQL 迁移已在 [PR #11 的 GitHub Actions run 32633212169](https://github.com/wlohf/Mnemox/actions/runs/32633212169) 通过真实 PostgreSQL 16 及其余远程门禁。
