## 已完成内容

- 新增 Alembic 修订 `20260809_05`：`projection_outbox.dead_lettered_at` 显式标记 DLQ 终态，并建立 `projection_outbox_worker_heartbeats` 非敏感心跳表与 `projection_outbox_retry_policy` 单例策略表。历史失败任务不保存当时的最大尝试次数，因此迁移不会猜测其终态，而是交给运行时对账。
- `OUTBOX_WORKER_RETRY_POLICY_VERSION` 与 `OUTBOX_WORKER_MAX_ATTEMPTS` 共同定义数据库规范重试策略。首个 DLQ-aware consumer 写入 `{policy_version, max_attempts}`；同一版本配置不同上限会快速失败；更高版本原子更新全局上限，较低版本的新版 consumer 会读取并使用该规范上限。因而策略升级后，低于新上限的失败任务会自动移出 DLQ；分页重放和用户显式重试仍会清空计数并重新入队。
- 新增用户范围失败队列与重试接口：`GET /api/learner-model/outbox/failures`、`POST /api/learner-model/outbox/failures/{id}/retry`。响应不含 payload、原始异常或其他用户任务。
- PostgreSQL 常驻 worker 以独立协程写入心跳，即使单个投影批次较慢也不会误判无消费者；配置要求 TTL 大于心跳间隔并保留调度余量。聚合快照只统计已知、活跃和失活消费者数量，不汇总会因实例重启而失真的计数器。SQLite/桌面端继续保持请求内单消费者路径。
- 公开 `/health` 保持无数据库聚合的轻量存活检查；DLQ、陈旧领取、积压年龄和跨实例消费者状态仅通过受保护的运维指标提供。积压年龄以可领取任务的 `available_at` 计算，历史重放不会误报长期积压。
- 新增受 token 保护且不出现在 OpenAPI 的 `/internal/outbox/metrics` Prometheus 端点。部署未配置 `OUTBOX_OPS_TOKEN` 时，该端点返回 404；该 GET 端点只读，不会初始化策略或改变 DLQ 状态。策略已初始化时指标会暴露数据库规范的策略版本和重试上限；未初始化时会显式告警，并与 worker 的状态变更日志共同承接告警，不引入未配置的 Slack/SMTP 投递器。
- 新增心跳、阈值和运维 token 配置，并补齐根 `.env.example`、`backend/env.example` 与 `docker-compose.yml`。

## 失败、降级与数据变更

- 本次迁移不可自动 downgrade；正式 PostgreSQL 升级必须先做快照并在升级后核对。升级失败的恢复路径是快照恢复并配套对应应用二进制，或使用理解新 schema 且禁用旧 consumer 的兼容版本；不能直接把应用回退到只认识 `20260809_04` 的旧二进制。
- 监控端点默认关闭，只有部署显式配置专用 token 后才可供内部 Prometheus 抓取；部署侧仍需为 alert code 或指标配置告警规则。
- DLQ 的人工重试是用户隔离的恢复入口，不替代根因修复；运维接口不暴露异常正文以避免泄露内部实现或用户数据。
- 发布时必须先停止不理解 DLQ 状态的旧 consumer；所有恢复消费的实例都必须具备版本化策略解析能力。修改上限时同时递增 `OUTBOX_WORKER_RETRY_POLICY_VERSION`，同一版本不得配置不同上限；已支持该策略的旧实例可读取数据库规范值并继续安全消费。
