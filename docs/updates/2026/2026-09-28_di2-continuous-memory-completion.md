# DI-2 连续记忆的功能补齐

本轮继续完善 DI-2，均为工作区变更，未提交或部署，也未修改真实用户业务数据。阶段状态以[路线图 0.2](../../roadmap.md)为准；前一轮实现见[DI-0～DI-2 交付记录](2026-09-28_dynamic-understanding-implementation.md)。

## 用户功能

- **串起不同会话中的经历**：同时查询 Graphiti 的实体和关系，再以与当前问题相关的实体查找相邻经历。可以从早期尝试找到后来同一主题下的方法失效或剩余卡点；不是只按原文是否重复出现关键词查找。
- **按时间回看原始依据**：学习画像中的连续经历检索展示时间、原始记录、图命中/SQL 补充和关联主题，可打开原始依据。时间线保留复盘的用户自述日期，不把补录日期伪装成经历发生时间。结果为近期相关经历保留位置，避免旧关键词命中挤掉后来的变化。
- **可恢复的操作入口**：支持重试失败任务、按当前来源版本重新抽取、清理失效图记录。重新抽取会增加该来源版本的抽取修订号；来源已变更时返回 409，要求先查看新内容。
- **可理解的用量**：展示当天 UTC 调用数、报告的 Token、缺失用量及按用户配置单价计算的费用。未报告用量或未配置价格时保留“未知”，不展示成免费。重建和清理不调用模型。

仍采用词法向量和 BM25，并增加实际图实体/关系查询，不宣称语义向量检索。相同实体名只是关联检索线索，不证明实体身份相同、因果关系成立或方法永久有效。图返回的推测性描述不直接作为聊天事实；聊天与 Coach 消费的仍是重新核验的 SQL 原文与来源。

## 生命周期和恢复边界

每个重建批次只处理一条经历，剩余来源版本通过现有 AgentJob 继续排队，不在单个租约里重建所有历史。重建复制已保存 SDK 结果并重新映射节点、关系及来源 UUID，在新的隔离图空间写入；最终核验来源和租约后才切换 SQL 可见指针。迟到重建不能重新激活已排除或修改的经历，失败空间保留清理检查点。

保存投影、记录图阶段检查点和安排后续批次同事务完成。恢复或用户重试不重复已经完成的候选/图阶段；原调用账本保留。停用后清理图空间，重新启用时可以直接恢复 SQL 中保存的抽取结果，无需再次付费抽取。凭据失效和重试耗尽也会安排废弃空间清理。

图检索前后重新读取来源与开关，刷新 ORM 缓存中的旧行；如果检索期间来源变化，该结果退出返回。如果期间关闭聊天/Coach 消费，本次上下文也不再传入。不同用户的后台任务不会因某一个用户已有运行任务而全部等待。

单次预计用量已经超过整日预算时直接报告不可执行，不每日无限重试；仅当天剩余预算不足时延到下一 UTC 日。

本轮不增加数据库表或迁移。仍使用既有 `20260928_30`、`20260928_31`；抽取修订、恢复检查点与用量摘要通过现有 JSON 字段保存。图查询有明确上限：最近 300 个有效已抽取来源、最多 12 个实体锚点、96 个相邻关系候选、4 秒查询期限；来源范围截断会返回标记。多会话实体不自动合并为全局事实，不做未经验证的关系冲突裁决。

## 验证和剩余门槛

- 真实 Graphiti SDK + 隔离 Neo4j 使用受控模型响应验证：实体关联、后来反例回看、SQL 基线对照、多条分批重建、抽取修订、关闭后免模型恢复、跨账号隔离、删除和回退。
- 独立边界测试覆盖：检索中的来源修改、消费开关变更、无效图来源、迟到重建、重试幂等与账本保留、多用户调度、阶段检查点恢复、凭据缺失后的清理及过大单次预算。
- 评测 runner 的受控集成覆盖完整报告、SQL/图两条路径、用量、费用未知和清理；这些结果验证工程实现，**不能记为真实模型质量通过**。

本轮结果：后端完整回归 **802 passed / 51 skipped / 70 subtests passed**；跳过项未计为通过，后续新增边界连同架构/API 门禁另跑 **16 passed**。显式启动隔离 Neo4j 后，真实 SDK 经历流程与评测 runner 专项 **2 passed**。前端完整回归 **40 个测试文件 / 176 项测试通过**；类型检查、生产构建、lint 及 `git diff --check` 通过。前一轮的 SQLite/PostgreSQL 迁移验证仍适用，本轮未新增迁移。

实际预检查结果保存在[DI-2 预检查记录](../../evaluation/di2-preflight-2026-09-28.json)：`graph_available=true`、`ai_configuration_ready=false`、`quality_verdict=not_run`。当前项目 SQLite 没有 AI 配置，现有 PostgreSQL 配置也没有可用密钥。没有发起外部付费模型调用。

**DI-2 的工程功能已经补齐，真实模型抽取质量和费用门槛仍未完成，因此本轮仍不将 DI-2 标记为最终验收完成。**受控案例能证明图检索路径被实际使用，不能证明它在真实模型和真实学习记录上稳定优于 SQL。

## 真实验收操作

在应用 AI 设置配置自己的 Coach 路由、模型和凭据；单价可选，未填写时费用未知。随后在后端运行，数据库连接应指向这份本人配置，图地址必须是独立测试实例：

```bash
python scripts/evaluate_dynamic_understanding.py --user-id <本人ID> \
  --isolated-graph-uri bolt://127.0.0.1:17687 --preflight \
  --output ../docs/evaluation/di2-preflight.json

python scripts/evaluate_dynamic_understanding.py --user-id <本人ID> \
  --isolated-graph-uri bolt://127.0.0.1:17687 \
  --max-model-calls 24 --max-tokens 120000 \
  --output ../docs/evaluation/di2-real-model-result.json
```

预检查不调用模型。正式运行使用合成中文经历、临时 SQL、现有用户 AI 配置及隔离图，不读取本人学习记录。调用上限同时受部署预算约束，不自动突破原限制。报告逐问题并排保存 SQL 基线与图增强结果、耗时、预期来源覆盖、实体/关系抽取、判断及实际用量；自动覆盖率不代替人评。按[评测格式](../../evaluation/dynamic-understanding-case-template.md)核验反例、未解决范围、过度泛化、费用与图增强收益。图清理失败仍保存报告及残留空间 ID，只删除本次登记的测试空间，不清空整个数据库。
