# 可靠性修复批次

本清单对应代码审查中的问题编号，记录于 2026-09-25。第一至第四批及问题 21 的代码已实现。未对现有部署执行迁移、重建容器、重写历史时间或轮换凭证；代码验收与上线操作分开记录。

## 第一批：安全、数据保留与核心流程失败处理

| 问题 | 级别 | 本批结果 |
| --- | --- | --- |
| 1 平台密钥进入用户可配置的提供商 | P0 | 默认提供商不再复制服务器密钥；用户调用不能回退使用环境密钥。历史密钥来源未知，一律隔离，必须明确重新填写用户自己的 Key 才可调用。迁移不删除历史密文；只改 URL 不能解除隔离。 |
| 2 Docker 写入未挂卷的目录 | P0 | Docker 显式指定 `/app/data`，为根目录增加持久卷，保留原 uploads/chromadb 卷；兼容数据库里的旧路径。提供默认只预览、拒绝覆盖冲突文件的迁移工具。 |
| 4 桌面重启更换 Origin | P1 | 持久化后端端口；首次升级复用最近的旧 IndexedDB 来源。端口被占用、配置缺失端口时明确报错，不静默分配新来源。Windows 实际安装包升级仍待验收。 |
| 7 AI 评估失败却判定及格 | P1 | 输出评估和章节复习要求有效评分结构；断网、解析失败、缺少评分或越界时返回 503，不生成假分数，不更改任务、熟练度或复习计划。 |
| 8 输出评估的局部导入导致崩溃 | P1 | 移除遮蔽全局 `Goal` 的局部导入；用真实关联任务验证正常评分、持久化与任务完成。 |
| 10 回滚后访问过期 ORM 用户对象 | P1 | 流式处理前保存标量用户 ID；回滚后的联网搜索等路径不再触发隐式异步数据库读取。 |
| 11 删除目标误删章节复习历史 | P1 | 删除目标只处理其任务引用，保留属于用户章节的 FSRS、重复次数和归档状态。 |
| 13 旧聊天流写入新会话 | P1 | 流绑定会话、登录代次和请求代次；切换会话或退出登录取消旧流，迟到回调不能写入当前会话。 |
| 17 切换页面丢失最后输入 | P1 | 切换笔记、组件卸载、页面离开前刷入待保存草稿；处理存储失败；显式保存期间的新编辑不会被旧结果覆盖，撤销编辑不会恢复旧草稿。 |
| 18 暂停时间被计入专注 | P1 | 暂停时停止 tick，手动结束扣除进行中的暂停；后端刷新同一计时记录时保留本地暂停状态。 |
| 19 错题提交失败仍提示成功 | P1 | 接口返回失败时保留复习输入并提示失败，仅在确认结果存在后显示成功。 |

## 第二批：计时归属、重试、历史时间与资料删除

| 问题 | 结果 |
| --- | --- |
| 3 番茄钟账户隔离 | 计时状态、历史、任务、任务集和背景配置按用户及账户创建时间隔离。切换账户会取消提醒、清空当前状态并阻断迟到回调；无归属的旧缓存不自动导入。 |
| 6 离线同步重复与中断状态 | 开始和结束共用持久客户端 ID；数据库按用户与客户端 ID 唯一。在线请求和离线批次调用同一业务路径，事件与计时原子提交；重试返回同一记录，矛盾的终态返回 409。保留中断、停止原因及实际时长，未同步记录不受历史缓存上限裁剪；重复开始也不替换当前计时。 |
| 14 历史时间 | 增加 `legacy / mixed / utc` 标记和明确指定记录的迁移脚本。预览包含原值、目标值及关联事件；执行核对快照、支持重复运行，拒绝夏令时歧义。旧记录已是 UTC 时使用 `--source-zone UTC` 确认；不自动推测来源。 |
| 9 资料删除 | 删除前处理题目、答题、错题、复习调度及概念关联；解除独立笔记、计时历史、学习会话和其他目标任务的外键引用。页面确认框说明删除范围，真实外键约束测试覆盖有题目资料的删除。 |

## 第三批：复习提交与调度唯一性

| 问题 | 结果 |
| --- | --- |
| 15 复习提交幂等 | 章节自评、AI 答案评估、错题和 Anki 均要求 `attempt_id`。请求回执、熟练度、FSRS 和事件在同一事务提交；相同请求重放返回原结果，复用标识更改评分被拒绝。网页持久保留未确认的答案与标识，Anki 使用持久离线操作 ID；AI 调用期间不持有写锁。 |
| 16 调度唯一约束 | 迁移将重复组所有原行存入 `review_schedule_merge_audit`，保留最新调度状态、最大重复次数及已有归档意图，再建立 `(user_id, item_type, item_id)` 唯一索引。所有常规调度创建使用数据库冲突处理，不重置已有 FSRS 或归档状态。合并不可逆，迁移 27 明确拒绝 downgrade；回退须恢复升级前备份。 |

## 第四批：聊天、检索与离线卡片

| 问题 | 结果 |
| --- | --- |
| 5 聊天中断持久化 | 调用模型流前提交用户输入及回答占位；首段立即保存，后续分段合并后先保存再发送。完成落库后才发送 `[DONE]`；取消或失败保留部分回答并标记未完成。进程硬退出时可能仍标记 `streaming`，历史页面同样显示未完成；同一 `turn_id` 重放已存结果，不再创建第二轮。 |
| 12 检索版本一致性 | 正文更新和索引待更新状态同事务提交；索引任务按版本提交结束状态，旧任务不能覆盖新版本。语义检索返回前在新 SQL 会话核对当前正文哈希、投影版本和片段哈希；无法确认的旧向量不进入答案，关键词检索使用当前正文。 |
| 20 Anki 离线 | 页面读账户 IndexedDB，创建、编辑、删除和评分先进入本机事务队列。新卡先确认创建再提交复习；丢响应或重启继续使用原操作 ID 和期望版本。并发设备进度变化进入显式冲突处理；待确认评分不重复入队，也不允许后续编辑将其覆盖。AI 生成和 CSV 导入明确需要联网；CSV 导出包含本机待同步内容。 |
| 21 完整分页 | Anki 与错题读取改用稳定 ID 游标遍历全部页；离线适配器只在完整拉取成功后核对远端删除。页面按页展示，避免旧的 200 条上限漏掉后续记录；分页间删除前面的行不会跳过后续行。 |

## 升级前必须处理

1. Docker 旧容器重建前备份 `/data`，按 [旧 Docker 数据升级](runtime-data-upgrade.md) 预览迁移并处理冲突。直接重建会让代码修复来不及挽救旧容器可写层的数据。
2. 曾被旧版本复制给用户的服务器密钥需要在供应商处轮换；用户需要重新填写自己的 Key。密钥来源不能从密文可靠判断，因此旧的合法 BYOK 记录也会暂时停用。
3. 桌面先备份用户数据，按 [桌面离线数据来源升级](desktop-origin-upgrade.md) 验证旧来源；多个旧来源的待同步数据不自动合并。
4. 按 [后续批次升级与数据核对](remaining-hardening-upgrade.md) 协调前后端升级，先备份再执行数据库迁移。复习请求新增必填 `attempt_id`，旧客户端需要一并更新。
5. 历史计时按来源分别生成预览计划，在备份库验证后再执行；旧在线时间、旧离线 UTC 时间不能混成一组。新代码只标记来源未知，不会自动平移整表。
6. 旧浏览器的 `pomodoro-storage`、任务及任务集无可靠用户标识，原内容保留。只从已确认归属的旧账户环境导出、人工核对，不把它们直接归给下一位登录用户。
