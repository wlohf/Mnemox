## 1. 产品定位

Mnemox 是面向个人学习者的 AI 学习教练。它不以通用问答为终点，而是把资料、学习目标、任务、笔记、复习、错题、专注记录和用户反馈连接为可追溯的学习闭环。

**产品哲学**：产品要解决的是"知道却做不到"的知行差距。它把经过验证的学习科学方法（间隔效应、检索练习、行为设计、元认知）转化为用户的默认行为，衡量标准是行为转化而非回答质量。

**北极星指标**（新功能立项必须回答改善其中哪一项）：

1. 建议执行率：Agent/Coach 建议被实际执行的比例。
2. 中断恢复时长：番茄中断或学习断档后回到学习的时间。
3. 复习按时率：到期复习按时完成的比例。
4. 每周有效学习时段数。

产品应让用户清楚看到：

- 当前正在推进的学习目标和最小下一步。
- 建议依赖了哪些资料、笔记、行为数据和记忆。
- Agent 将要写入什么内容，以及写入前的确认入口。
- 学习行为如何影响复习、画像和后续建议。

## 2. 目标用户与场景

| 用户 | 核心诉求 | 典型场景 |
| --- | --- | --- |
| 备考或自学用户 | 将长期目标拆成可执行动作，持续推进 | 制定计划、开始学习、课后复盘 |
| 重度资料学习者 | 在自己的资料中问答、记录与复习 | 上传课程资料、围绕章节提问、整理笔记 |
| 容易中断的学习者 | 获得低打扰、可执行的提醒和补救建议 | 番茄钟中断、任务逾期、学习动力下降 |
| 有复盘习惯的用户 | 基于行为证据理解效率和薄弱点 | 查看 EDA、画像、错题和复习积压 |

## 3. 核心学习闭环

```text
资料/目标输入
  -> 计划与今日聚焦
  -> 对话、番茄钟、笔记、练习
  -> 行为事件与学习证据
  -> 画像、记忆、复习与风险识别
  -> Agent/Coach 给出草案或建议
  -> 用户确认、执行与反馈
  -> 下一轮个性化调整
```

其中，涉及创建或修改目标、任务、日计划、笔记、长期记忆等数据的 Agent 动作，必须先以草案呈现，用户确认后才能写入。

### 3.1 四层学习智能需求

产品后续功能必须明确自己消费和写入哪一层，不能将所有数据混入向量检索或一个 Agent 提示词。

| 层 | 面向用户的能力 | 需求边界 |
| --- | --- | --- |
| 资料上下文层 | 在资料、笔记和已授权记忆中检索并引用证据 | 混合检索结果必须有来源、版本和降级状态；不能宣称资料未表达的结论 |
| 概念图谱层 | 查看知识点、先修关系、资料挂接和薄弱点下钻 | 关系必须可追溯、可人工改正；概念关系不等同于用户掌握度 |
| 时态记忆层 | 让系统理解目标、偏好、困惑和状态变化，而不是永久记住过期标签 | 记忆必须有来源、有效时间、置信度和审核/纠错入口；用户可导出和删除 |
| 学习者模型层 | 显示概念级掌握状态、遗忘风险、复习和下一步建议 | 结论必须展示证据与更新时间；不能由单条聊天记忆、学习时长或 LLM 推断直接决定 |

学习者模型至少区分直接学习证据与间接行为信号。答题、回忆、解释、应用、提示次数和复习结果是状态更新的主证据；学习时长、频率、重复提问和中断情况只用于校准置信度、风险和干预策略，不能单独证明掌握。

### 3.2 可解释的学习决策

- “为什么推荐这个概念/复习项”必须能显示目标关联、先修关系、最近直接证据、遗忘风险和可用时间等理由。
- 用户应能修正概念关系、记忆声明和学习状态；人工修正必须保留来源，不能被后台模型静默覆盖。
- FSRS 负责复习时间；学习者模型负责结合目标、先修图与证据判断学习优先级。两者的结果和用途必须在产品中区分。
- 产品可使用 Graphiti 等时态记忆引擎辅助检索用户状态变化，但规范记忆、原始事件和学习状态必须保留在本系统可审计的数据模型中。

## 5. 质量与约束需求

### 5.1 安全与隐私

- API 必须基于登录态识别用户；所有用户数据读取、更新、删除都必须绑定当前用户。
- 上传文件必须限制类型和大小，文件访问必须通过认证并防止路径穿越。
- AI Provider Key、Tavily Key 等敏感配置不得明文存入前端或提交到仓库。
- 资料、笔记、网页搜索结果和工具输出均属于不可信上下文，不能覆盖系统指令或绕过用户确认。

### 5.2 可靠性

- 未配置 AI Key、Embedding 服务异常、搜索服务失败或 Agent Planner 超时时，核心学习流程不能整体失败。
- RAG 语义检索不可用时必须回退到关键词检索，并向用户提示当前检索状态。
- 流式对话的后处理步骤失败不能回滚已持久化的聊天内容。
- 离线操作应被排队、可观察、可重试；冲突需要有明确的用户处理策略。

### 5.3 可用性

- 用户应在主工作区快速找到当前目标、今日动作和到期复习。
- Agent 建议应展示来源证据、风险原因和预期写入结果。
- 界面应支持键盘操作、清晰焦点状态、足够对比度和窄屏布局。
- 自动化提醒默认低打扰，遵循用户偏好、免打扰时段、冷却时间与每日上限。

### 5.4 验收与数据治理

- “完成”必须同时有代码、迁移、测试、可观测性和验收证据；只有接口或字段不算完成。
- 四项北极星指标必须记录原始事件，并明确分子、分母、时间窗、时区、去重和异常处理。
- 后台任务必须具备幂等键、重试/退避、超时/取消、运行锁和失败状态；应用重启或睡眠恢复后不得静默丢任务。
- 概念抽取、Agent 工具结果和 Coach 日志应可追溯、可脱敏、可按用户删除；后台 LLM 调用要有用户级成本上限和熔断。
- Obsidian 同步与写回必须有稳定 vault/file 标识、冲突/删除策略、用户可见差异和可回滚操作。
- 关系型数据与原始资料是规范来源；向量库、图数据库、Graphiti 和工作流 checkpoint 都必须可由规范数据重建，不得单独持有唯一用户事实。
- 领域写入、`LearningEvent` 与索引/图谱/学习状态投影必须具备可重放的 outbox/任务语义；投影失败、重试、版本和删除结果应可观察。
- 每条概念关系、记忆声明和学习状态更新必须保留来源、模型/规则版本、置信度和关联事件；检索、图谱、记忆和学习状态各自建立离线质量集与回归测试。
- 用户删除、权限变更、资料更新后，相关向量、图、时态记忆和缓存投影必须在可观测任务中刷新或清除；失败不能静默留下可检索残留。

## 6. 下一阶段需求优先级

> 阶段顺序、验收标准和冻结清单的权威来源是 [路线图](roadmap.md)；本节仅概述需求含义。架构边界与候选技术依据见 [2026-08-03 决策文档](superpowers/specs/2026-08-03-learning-intelligence-foundation-architecture.md)。

### 立即（小胜利轨道，主体与版本化迁移已实现）

1. 自引激励收尾：低动力场景下引用用户自己的笔记原文（注明出处），含防疲劳冷却与采纳反馈。
2. FSRS 复习调度：以 `py-fsrs` 替换手写 SM-2 风格调度，保留存量复习历史。

### P0：Beta 收口

1. 系统性完成多用户授权审计，重点检查详情、更新、删除和文件访问接口。
2. 统一 Prompt Injection 防护层，为资料、笔记、搜索和工具结果建立明确的不可信上下文边界。
3. 收口 RAG 状态的产品语义：资料侧栏和设置入口已展示在线/关键词回退/最近错误；还需让聊天等入口保持同一状态含义，并用浏览器 E2E 验证降级提示。
4. 保留 API 冒烟，同时补真实浏览器/桌面 E2E，覆盖 Agent 草案确认与执行。
5. PostgreSQL 16 演练库的 v1.3.0 到当前 head 升级测试已完成；正式生产库仍须在发布窗口先做快照，再执行升级与数据核对。
6. 仓库卫生：清理明确过期的 `release/` 资产，规范提交分支和未提交文件状态。

### P1：四层学习智能底座（Phase 1）

1. 规范底盘：为学习证据、用户概念状态、时态记忆声明和投影 outbox 完成版本化迁移、回放、删除和重建语义。
2. 学习者模型：以 `learner_evidence` 和 `user_concept_state` 替代 `Concept.mastery` 的混合语义；先完成可解释的直接/间接证据聚合、人工修正和一次复习到状态更新的闭环。
3. 检索底座统一：先让一个真实业务流只依赖 `ContextStore`，再迁移 RAG、笔记和记忆；以质量集和 Windows/删除/降级测试评估 Qdrant，未通过则保留可替换基线。
4. 概念图谱：完成真实 PostgreSQL 演练、自动上传闭环、人工改名/合并/删除、关系来源与抽取质量评测；只有多跳查询或图谱编辑的价值成立后再评估 Neo4j。
5. 时态记忆：补全来源、有效时间、失效、冲突、用户审核和删除闭环；以筛选后的状态变化 episode 评估 Graphiti，不能将原始聊天全量写入。
6. Obsidian vault：先收口拉取式同步的稳定 ID、冲突/删除/并发语义；watchdog 作为后续增强，不与 MVP 混标。
7. 联想引擎：接入 Coach 呈现、shown/feedback/采纳事件和保守阈值调参。
8. 概念级体验：完成概念地图、先修缺口、资料小节下钻与学习建议理由展示。

当前实现状态：`learner_evidence`、`user_concept_state`、`projection_outbox`、学习者模型 API、前端证据下钻和 SQLite/PostgreSQL 迁移演练已完成；525 条分页重放、跨用户/概念隔离、幂等/重试/崩溃恢复、严格 API 输入校验和聚焦回归均有证据。校准报告当前为 0 个 holdout case，真实数据校准、常驻 worker/监控与移除 legacy 字段按此顺序后置，Phase 2 不提前展开。

### P2：Agent 升级（Phase 2，垂直切片）

1. AgentRuntime：以一个主动触发场景比较原生 AgentKernel 与 LangGraph；只有同时满足持久化、SSE、取消/恢复、草案确认、旧 Planner fallback、回放、隔离、降级和桌面打包时才正式采纳任一运行时。
2. 后台自主性：先实现启动/恢复 catch-up 和一个触发器，再增加定时任务；所有任务可重试、幂等、取消和观测。
3. 干预效果自学习：先落曝光→接受→执行→行为变化链路和指标看板，确定性分桶先于 bandit；bandit 必须有样本门槛和回滚开关。
4. 知识巩固与周报：通过四层路由组合资料证据、概念关系、时态记忆和学习状态；定义来源追溯、文件所有权、冲突和回滚后，再开放 Obsidian 写回。

### P3：生态与公开试用（Phase 3）

1. MCP Server：向外部 AI 客户端暴露画像、图谱、错题与复习状态。
2. 语音：TTS 激励朗读 → STT 输入 → 全双工对话，依次评估推进。
3. 一键 Demo 数据、发布自动化；AnkiConnect 集成评估。
4. 在隐私与授权边界明确后，评估学习伙伴、共同番茄钟和轻量监督功能。

### 持续项（随相关阶段推进，不单独立项）

- 搜索来源可信度排序、去重、缓存与引用展示。
- 离线同步冲突检测、差异展示与用户决策入口。
- 上下文 token 预算分层：由 `ContextStore` 分层加载能力承接（见 2026-08-03 决策）。
- LLM 成本、日志脱敏、数据保留/删除和后台任务运行语义：作为 Phase 0/Phase 2 的横切验收项推进。

## 7. 非目标

- 不把 Mnemox 做成只追求对话能力的通用 AI 聊天产品。
- 不与成熟单点工具正面竞争：Markdown 编辑器功能冻结（保留现状），复习界面长期可交给 Anki 等成熟软件，Mnemox 聚焦图谱、行为数据与教练策略。
- 不在未通过安全、持久化、桌面分发、确认式写入与回放验收前锁定任何通用 Agent 运行时；LangGraph 仅保留为受控 Spike，不是既定依赖。
- 不使用 Microsoft GraphRAG；LightRAG 仅作为离线评估、提示和检索策略的参考，不进入运行时依赖。
- 不把 Cognee、Mem0、Graphiti、Qdrant 或 Neo4j 当作用户事实、掌握度或权限数据的唯一来源。
- 不实现任何站点音视频下载功能；音频需求以本地导入与官方嵌入播放器满足。
- 不在没有明确用户授权和数据隔离设计前上线多人社交、公开资料或跨用户推荐。
- 不以增加自动写入数量为目标；任何高影响写入都应保留草案和确认步骤。
- 不以大规模生产部署为当前阶段目标，当前优先级是单用户/小范围 Beta 的稳定性、可解释性和学习闭环质量。
