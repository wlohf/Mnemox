# 动态用户理解与连续辅导实施计划

> 日期：2026-09-28
> 依据：[已确认的产品方向与领域契约](../specs/2026-09-28-dynamic-user-understanding.md)
> 本文拆解执行任务；阶段状态以[路线图](../../roadmap.md)为唯一来源。复用代码不代表新增能力已验收。

## 1. 首条交付流程

用户完成学习或复盘后，系统从记录中提出一个有依据、带适用条件的观察或假设；用户能够查看依据、纠正或忽略。后续辅导记得已经尝试的办法，并结合新记录更新判断。需要改变任务或计划时，通过既有草案和确认入口执行。

番茄钟、关联任务、复盘和 Coach 结果是第一批输入。假设内容保持开放，不能仅交付几个固定的“最佳时段”“专注型人格”规则。

## 2. DI-0：可靠证据与评测契约

**先阅读/复用：**

- `backend/app/models/pomodoro.py`、`learning_event.py`、`daily_plan.py`、`coach.py`。
- `backend/app/services/profile_service.py`、`learning_event_service.py`、`learning_snapshot_service.py`。
- `backend/app/services/coach_action_attempt_service.py`、`north_star_metrics_service.py`。
- [功能评估](../../project-functional-assessment-2026-09-28.md)与现有时间、同步、归因测试。

**任务：**

1. 为首批数据定义来源 ID/版本、发生/记录时间、时区、实际与计划时长、结果、缺失和质量标记。
2. 检查并修正会影响分析的时区、重复事件、开始/结束重复计时、Demo 混入和任务状态不一致；历史记录不做无依据补全。
3. 区分原始经历与派生摘要，建立同源证据分组；保留异常背景和不可比较的样本说明。
4. 修正现有画像及提示中的过强表述，例如将按数量得到的“最佳时段”作为活动分布解释，不能让旧分数成为新系统的事实依据。
5. 建立冷启动、重复、单一场景、大量同源记录、真实异常、近期变化、用户纠正的合成回放，并准备真实任务评测格式。

**退出证据：** 相同规范输入可以重算得到一致统计；用户自然日正确；重复与派生记录不增加独立证据；缺失与零可区分；基础任务/计时流程回归通过。

## 3. DI-1：开放假设与动态评估

**先阅读/复用：**

- `backend/app/services/agent_memory_learning_service.py`、`memory_declaration_service.py`。
- `backend/app/ai/factory.py`、现有结构化抽取、预算和持久任务设施。
- `backend/app/services/learner_model_service.py`、`learner_model_calibration_service.py` 的证据边界。

**任务：**

1. 实现最小经历/证据引用、候选规律、评估修订的存储与 DTO；具体模型按 ADR 逻辑契约设计，不提前拆出通用建模平台。
2. 让现有 AI 根据有界输入提出候选，返回适用条件、来源引用、反例/未知项及后续可观察信号；无匹配来源的引用拒绝入库。
3. 独立评估样本、覆盖、质量、支持和反例。明确指标可选轻量区间估计；不能操作化的判断停留为未验证，不采用模型自报概率。
4. 支持版本化的新增支持、争议、待复查、替代、撤回及用户纠正；条件不同的规律允许共存。
5. 提供查看依据、估计身份、适用范围和纠正/忽略/删除的功能入口，复用现有页面，不安排样式重做。
6. 沿用已有 API/事件授权、事务和删除边界；自动候选不自动写为已确认事实，不更新掌握度。

**退出证据：** 小样本可以不下结论；大量偏置记录不能泛化；同源重复和 AI 自我引用不能增强支持；新反例可修正旧判断；删除和两用户隔离通过。SQL-only 模式可完整使用候选与评估功能。

## 4. DI-2：Graphiti 连续记忆进入产品流程

**先阅读/复用：**

- `backend/app/services/graphiti_temporal_service.py`、`graphiti_shadow_service.py`。
- `backend/app/services/projection_outbox_service.py`、`projection_outbox_worker.py`。
- 现有聊天检索、Coach 学习快照、Graphiti 和 Neo4j 集成测试。

**任务：**

1. 新建或扩展独立 episode 适配层，保留当前 model-free Temporal V1 接口契约；分别声明事实、用户说明与未验证假设，不能复用已确认事实过滤器混装。
2. 选择有意义的文本/JSON 经历，接入真实实体/关系抽取与适用检索；复用 AI 配置，记录各类模型用量、预算、超时和失败。
3. 规范保存输入版本、抽取结果及来源映射，再投影到隔离的用户/对象空间；证明图可以从已保存结果重建，重新抽取产生新版本。
4. 通过现有持久任务/outbox 增量摄入、更新和删除，验证幂等、旧版本迟到和重启恢复。
5. 把检索接入聊天/Coach：回答“上次卡在哪里、试过什么、哪些问题已解决、现在有什么变化”，结果回 SQL 核验。
6. 图不可用时使用现有 SQL 记忆与记录，说明增强能力不可用；不能把未调用图服务的回退结果标记为 Graphiti 效果。

**退出证据：** 隔离 Neo4j 上真实 Graphiti episode 流程、跨会话查询、时间变化、纠错删除、重建和故障降级通过；有少量真实模型抽取质量与成本记录。现有 BM25-only 测试不代替本阶段验收。

## 5. DI-3：建议结果闭环与知识补弱

**先阅读/复用：**

- `backend/app/services/coach_learning_service.py`、`coach_action_attempt_service.py`。
- `backend/app/services/weekly_learning_report_service.py`、`learning_recommendation_service.py`。
- `backend/app/services/graph_store/`、`backend/app/routers/knowledge.py` 的现有学习路径。
- 前端既有 Agent、计划、番茄钟、记忆及知识功能入口。

**任务：**

1. 建议引用生成时的假设与证据版本；记录展示、采纳、开始、领域完成和后续结果，区分这些状态。
2. 让真实行动和后续反馈触发重评；用户没有响应时记录未知，不自动判断拒绝或失败。
3. 阶段复盘展示观察、新增支持/反例及判断变化；可以纠正、忽略或查看原记录。
4. 贯通 Neo4j 补弱路径：卡点/错题 → 有依据的前置路径 → 诊断 → 可确认的任务草案 → 重测。明确关联不证明原因，最短路径不自动是最优计划。
5. 保留 Coach 冷却、免打扰和用户偏好；诊断结果、用户声明与行为假设不越权替代直接学习证据。

**退出证据：** 真实前后端完成一次建议到结果再到判断修订的流程；刷新、重启、重试不重复创建任务或增加证据；计划/任务状态一致；路径关闭或不可用时正确说明能力边界。仅生成分析报告不算闭环完成。

## 6. DI-4：长期验证与按需增加模型

1. 按时间回放“当时已知信息 → 当时判断 → 后续结果”，相关会话不随机拆分到发现与验证两侧。
2. 以现有统计和会话摘要作为可用基线，比较抽取、记忆召回、过时判断、无依据判断、纠正响应和模型成本。
3. 使用真实/授权脱敏样本做中文及必要的双语人评；记录支持、反对和未验证结果，避免只展示成功案例。
4. 建立真实使用基线后，在下一轮独立观察前登记目标、样本规则、窗口和停止条件；观察行为结果、打扰反馈和成本。
5. 仅在已定位的问题上评估独立情感模型、变化检测、其他统计/预测方法。记录相对基线的收益、成本、校准与回退方法；不因记录变多就自动启用复杂模型。

**退出证据：** 能解释哪些判断可靠、哪些仍未知、用户变化时是否及时修正，以及新增图记忆是否改善了具体任务。合成回放证明工程正确性，不证明真人效果或因果。

## 7. 每阶段共用的交付约束

- 对确有必要的新增 schema 提供 SQLite/PostgreSQL 迁移和历史数据兼容验证；旧画像不自动转成已证实特性。
- 正文、依据和派生对象的删除/纠错可传播至图与缓存；失败可重试，失效内容先退出可见检索。
- 分别控制候选分析、图记忆和策略消费；默认部署不因安装 SDK 强制启动图服务。关闭增强能力后，基础记录和既有学习流程可用。
- 后台分析使用既有幂等、事务外模型调用、预算、租约和重试设施；不再搭建一套平行调度框架。
- 完成契约/服务测试后验证相关 API 与真实产品流程；图集成使用临时实例，真实模型质量与用量单独记录。
- 每阶段更新路线图状态、进度证据和周期记录；实现、测试、真实质量、部署分别描述，不把文档确认记成能力已交付。
