# Mnemox 知识层、检索底座与 Agent 架构决策（历史摘要）

日期：2026-07-26

状态：部分仍有效；2026-08-03 决策已覆盖其中的学习者模型、候选技术和阶段顺序

当前依据：[学习智能底座架构决策](2026-08-03-learning-intelligence-foundation-architecture.md) · [路线图](../../roadmap.md) · [技术基线](../../technical.md) · [进度文档](../../progress.md)

本文仅保留仍影响当前实现的历史结论，避免旧 schema、旧选型和旧阶段状态误导后续开发。2026-07-26 的完整原文仍可通过 Git 历史追溯。

## D1. 关系型核心继续作为规范来源

- SQLite / PostgreSQL 中的领域数据、事件、权限和审计记录是规范来源，不因引入向量库、图数据库或工作流运行时而迁移事实所有权。
- 所有用户数据访问必须绑定 `user_id`；删除、权限变更和数据更新需要同步清理可重建投影。
- 复习调度采用 FSRS 优先、兼容降级的策略。正式数据库升级必须通过版本化迁移、备份、数据核对和回滚预案。

## D2. 概念关系与学习者状态必须分离

- 概念、先修关系和资料挂接属于可审核的领域图；关系需要来源、置信度和人工修正入口。
- 用户掌握度不属于 `Concept` 实体。当前权威来源是 `learner_evidence` 和 `user_concept_state`；`Concept.mastery` 仅在兼容周期内回退读取。
- Microsoft GraphRAG 不进入路线图；是否评估 Neo4j 取决于 SQL 图在真实多跳或编辑场景中是否出现明确瓶颈。

## D3. 检索接口先于具体供应商

- 业务层通过 `ContextStore` 统一资料、笔记和可检索记忆的入库、召回、分层加载与删除语义。
- 向量或搜索组件是可替换投影，必须支持用户隔离、更新、删除、重建和无 embedding Key 时的降级。
- OpenViking 已因 Windows 桌面分发和依赖足迹不满足门槛而否决，证据见 [OpenViking Spike 结论](2026-07-26-openviking-spike-result.md)。当前候选及验收标准以 2026-08-03 决策为准。

## D4. AgentRuntime 不拥有领域规则

- 无论使用原生 AgentKernel 还是通过受控 Spike 评估 LangGraph，鉴权、用户隔离、草案确认、撤销、审计、Coach 治理和学习证据计算都由 Mnemox 领域层负责。
- 只读工具可以在约束内执行；写入类动作先生成可检查草案，用户确认后才进入领域事务。
- 外部资料、笔记、搜索和工具结果均按不可信上下文处理，AgentRuntime 不得绕过该边界。

## D5. 自学习只优化干预策略

- 可学习范围限于触达时机、技能选择、措辞和频率，不能学习绕过确认、权限、免打扰、每日上限或安全规则。
- 先记录不可变的曝光、接受、执行和后续行为事件，再定义归因窗口和确定性分桶；样本量、灰度和回滚证据不足时不引入 bandit。
- 四项北极星指标为建议执行率、中断恢复时长、复习按时率和每周有效学习时段数。

## D6. 集成遵循稳定边界

- Obsidian 先完成带稳定 vault/file ID、冲突和删除策略的拉取式同步；后台监听和写回后置，写回必须可见且可回滚。
- AnkiConnect、MCP 和语音属于后续生态能力，不得提前扩大 Phase 1 的数据边界。
- 不实现站点音视频下载；新增页面或编辑器功能必须能说明它降低了哪个核心学习行为的执行阻力。
